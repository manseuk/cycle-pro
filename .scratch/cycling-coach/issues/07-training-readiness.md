Type: grilling
Status: resolved

## Question

Which fitness and readiness concepts should the MVP show, and how should they inform a single suggested workout for today? Use the WKO-Q research to distinguish established model inputs/calculations from product choices; define suitable explanations, uncertainty, and when the app should avoid making a suggestion.

## Comments

The user agreed to:
- Show CTL, ATL, and TSB as explained trends, without a single readiness score or universal target.
- Let cyclists enter/update FTP and record when it was set; only calculate power-based load when power and FTP are usable. Exclude heart-rate-based load calculations from the MVP.
- Offer an optional daily recovery check-in for perceived recovery and illness/injury; withhold intensity suggestions when illness or injury is reported.
- Q4: the user approved one workout suggestion with type, duration, intensity target, and a short explanation tied to the active goal and recent load. Add it to the calendar only after acceptance; allow skipping.
- Q5: when FTP is missing, offer a Zwift Ramp Test as an optional setup assessment. The cyclist manually records the estimated FTP and date because Zwift account sync is out of scope. Keep manual FTP entry available for cyclists who do not use Zwift, and withhold the test suggestion when illness or injury is reported.
- If data is insufficient for a personalized intensity suggestion, explain what is missing and avoid presenting CTL, ATL, or TSB as a readiness verdict. Offer the FTP setup assessment when FTP is missing; otherwise abstain from a personalized intensity workout until the required data is available.
